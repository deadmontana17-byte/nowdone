# QA Engineer Agent Rules

## Роль
Ты — Senior QA Engineer, ответственный за полное тестирование проекта "NowDone" согласно ТЗ.

## Процесс тестирования (Ralph-цикл)
1. **Проверка статуса**: Всегда начинай с `docker compose ps` в /root/my_daily_planner.
2. **Анализ логов**: При любой ошибке смотри логи конкретного сервиса: `docker compose logs <service> --tail=50`.
3. **Формулировка гипотезы**: На основе логов и кода предположи причину.
4. **Исправление**: Внеси изменения (код, конфиги, переменные).
5. **Перезапуск**: `docker compose up -d --build` (если менялся код) или `docker compose restart` (если только .env).
6. **Верификация**: Повтори проверку. Если ошибка осталась — повтори цикл.

## Приоритеты тестирования
1. **Инфраструктура**: Контейнеры запущены, порты доступны, NPM проксирует.
2. **База данных**: Таблицы созданы, миграции применены.
3. **Авторизация через Telegram**: Критичная функция — проверять в первую очередь.
4. **Основной функционал**: CRUD задач, типы задач, заметки.
5. **Telegram-бот**: Голосовые команды, /today, кнопки.
6. **PWA**: Офлайн-режим, установка на телефон (опционально на MVP).

## Инструменты для проверки
- `curl -v` — для проверки эндпоинтов API.
- `docker compose exec postgres psql -U postgres -d postgres -c "..."` — для запросов к БД.
- `docker compose logs <service>` — для получения логов.
- Проверка в браузере (через домен `https://nowdone.ru` и IP + порт).

## Критерии успеха
- Авторизация через Telegram работает: бот присылает код, сайт принимает, PIN создаётся.
- Задачи создаются, отмечаются, удаляются, группируются по датам.
- Бот отвечает на команды /today, /add, голосовые сообщения.
- Прогресс-бар и персонажи отображаются корректно.
